# 모바일 HUD와 탐험가 생성 (2026-10-03)

## 구현

- 첫 기기: 게스트/이메일 로그인 → 이름 → 꾸미기 → 완성 미리보기 → 탐험 시작. 게스트는 EC2/Supabase 접속 없이 시작한다.
- 기존 저장: 진행도·펫·알을 유지하고 모자 3종을 새 외형의 포인트 색/캡으로 변환한다. 기존 이름이 있는 저장은 생성 과정을 강제하지 않는다.
- 새 이름은 한글/영문/숫자 2~12자, 기본 금칙어 검사, 중복 허용. 내부 계정/멀티플레이 ID와 별개다. 기존 이름은 변경하지 않는 한 유지한다.
- 공용 `ExplorerAppearance`: 피부 8, 얼굴 8, 머리 12, 머리색 10, 의상 8, 포인트 색 8, 장식 8, 백팩 4. 추천 스타일 4개와 전체 랜덤을 제공한다.
- 기존 복셀 뼈대와 판정을 보존하고 부위 메시의 색상/기하를 변경한다. 머리/장식/가방은 부위에 병합하므로 장식마다 draw call을 추가하지 않는다. 원본 자산은 수정하지 않는다.
- 플레이어, 동료, 원격 친구, 생성 미리보기, 설정의 꾸미기에서 같은 렌더 함수를 쓴다. 호스트 인계에도 외형을 보존한다.
- 계정 진행 JSON에 `explorerAppearance`, `explorerCreatedAt`을 저장한다. 기존 cloud save 스키마는 JSON 필드를 보존하므로 DB migration은 추가하지 않았다.
- 방 입장/외형 변경 시 외형을 보내고, 변하지 않은 외형은 클라이언트/릴레이 양쪽 delta에서 제외한다. 서버는 허용된 기본 외형 ID만 통과시킨다.
- 상단은 2줄 76px 요약, 접으면 110×48px 최소 시계. 접기 버튼을 독립시키고 180ms 전환, reduced-motion 대응을 넣었다.
- 속도/날씨/권장을 두 줄로 압축했다. 탐험가는 요약 카드 → 이름/위치/속도 목록으로 펼치며 바깥 터치·설정·HUD 접기로 닫힌다.
- 친구 메뉴는 설정에 유지한다. 초대 코드 생성 후 표시/복사/입장/방 나가기를 제공한다. 상시 방 코드와 ‘혼자 플레이’ 버튼은 없다.
- 이모티콘은 조이스틱 오른쪽 44px 버튼 → 3×2 선택창, 바깥 터치/큰 패널/8초 미사용 시 닫힘. 1.8초 재사용 간격, 2.5초 표시와 마지막 350ms fade를 공유한다.
- 동료 기본 2, 최소 0, 드물게 3. 전체 5자리 중 실제 친구용 1자리는 동료로 채우지 않는다. 사용자 화면에 동료 구현 방식을 설명하는 문구는 없다.

## 검증

- `npm run build` / `qa:typecheck` / `qa:lint`: 통과. 샌드박스 상위 경로 접근 실패는 권한을 받아 재실행했다.
- `scripts/qa/simulated-players.mjs`: 스냅샷, 5분 진행, 실수, 전투, 인사 답례/무시, 입퇴장, 슬롯 양보, 호스트 인계 통과.
- `scripts/qa/local-first-ui.mjs`: 오프라인 플레이/저장, 코드 입장, 이동/이모티콘, 호스트 인계, 장애/복구, Auth/RPC fixture 클라우드 복원 검사.
- `qa:explorer-profile`: 선택지 수, 이름 검증, 기존 저장 변환, 외형 저장, 동일 이름, 서버 ID 검증, 위치 delta에서 외형 제외 통과.
- `qa:mobile-hud`: 새 생성/수정/재접속, 320×568·360×800·390×844·430×932, HUD 접기/펼치기, 탐험가/초대/이모티콘, 버튼 경계, 조작 위치 유지, 조이스틱 drag, 튜토리얼, safe area 47/34px 검사.
- 화면 결과: `artifacts/test-results/mobile-hud/`. 기존 시각 기준 이미지는 갱신하지 않았다.
- `qa:unit` 전체는 통과하지 않았다. `scripts/test-game.mjs:92`의 알 보관 테스트가 6칸을 최대 보관함으로 가정하여 실패한다. **수정 전 9e44143의 GameState로도 동일 오류가 재현**된다.
- 뒤의 명령을 개별 실행하면 `qa/unit.mjs:28`은 삭제된 `tickDamage` 호출, `qa/progression.mjs:15`는 과거 체력 100~495 기준 때문에 실패한다. 실패를 감추려고 테스트를 삭제/완화하거나 게임 밸런스를 변경하지 않았다. `qa/balance.mjs`와 `qa/multiplayer.mjs`는 통과했다.

## 확인이 필요한 부분

- 화면 검사는 데스크톱 Chromium의 터치/모바일 뷰포트 에뮬레이션이다. 실제 iPhone Safari/Android/Toss WebView, 실기기 FPS 검증이 아니다.
- 이메일 로그인은 Supabase 메일 링크 및 OTP API를 연결하고 fixture로 검사한다. 실제 메일 발송/수신과 프로젝트 Redirect URL·메일 템플릿은 실계정 확인이 남는다. 템플릿이 링크만 제공해도 링크로 돌아와 세션을 복원한다.
- 금칙어 검사는 초기 기본 목록이다. 우회 표현 및 운영 신고/제재 체계까지 제공하는 필터는 아니다.
- 모든 초기 외형은 기본 제공이며 능력치를 바꾸지 않는다. 스테이지/업적/유료 꾸미기와 기지의 물리적 옷장 오브젝트는 후속 콘텐츠다. 현재는 설정의 꾸미기에서 언제든 무료로 바꾼다.
- JS 전체 chunk gzip 합계에는 기존 Supabase/SDK 등 지연 로딩 chunk도 포함된다. 이번 검증에서 초기 전송량/실기기 성능 예산 충족을 주장하지 않는다.
