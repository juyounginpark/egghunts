# 구현 작업 계획

## 기지 표시 스피드와 실제 이동 분리 (2026-09-24)

- `speed`는 성장 수치 표시/서버 전달을 유지하고 `movementSpeed`는 기지에서 2, 탐험에서 `speed`를 사용한다. 공통 이동 함수와 온라인 예측·보정에 함께 적용한다.
- 기존 이동 진단 기록에서 서울 리전, DB revision 충돌 재시도와 최대 약 782ms 응답을 확인했다. 실시간 이동과 저장을 분리하는 서버 구조 변경은 이번 수정에 포함하지 않는다.
- 이번 소규모 변경의 자동 QA/실기기 측정은 별도로 실행하지 않는다.
- 화면 오른쪽 아래에 작은 패키지 버전/배포 커밋 번호를 표시한다. GitHub 빌드는 GITHUB_SHA를 사용하고 로컬은 dev로 구분한다. 터치 이벤트는 가로채지 않는다.

## 동행·운반 표시와 보관소 획득 후속 (2026-09-24)

- 서버 장착 목록, 상대 리그 걷기/운반, 비동기 펫 교체, 알 이펙트 초기화와 variant를 수정했다. 두 브라우저 fixture는 실제 방 엔진을 사용하며 공개 서버의 실제 2인 접속 시험과 구분한다.
- HP 0 준비 완료 알을 보관소에 유지하고 명시적 획득 명령에서 소유/기지/준비 상태를 검사한다. 기존 부화 단위 검사는 명시적 claimHatch 흐름으로 갱신해 수동 실행용으로 유지한다.
- 기지 현재 스피드 적용 및 방 진행도 속도 표시, 귀환 알 이름/등급 강조 공지를 추가했다. 알/펫 ID와 기존 보유 기록은 유지한다.
- 이동 실측 수치와 남은 지연은 `peer-followup.md`에 기록한다. 이번 새 부화 연출의 모바일 시각 검수와 휴대폰 실기기 검사는 미실행이다.

## 이동 실측 후속·마을·플레이어 표시 (2026-09-24)

- 실제 Supabase 게스트 방에서 정상 응답과 0~250ms 추가 지연의 이동·정지·알 획득·보스 추격을 측정한다. 이전 선형 보간의 패킷 사이 정지와 로그인 시계 오차를 확인해 수정한다.
- 플레이어 특성 UI·획득·효과를 제거하고 레벨/XP/보유 자산을 유지하는 구 저장 마이그레이션과 폐기된 서버 명령 거부를 검사한다.
- 산맥·문·울타리와 입구 통행, 다섯 운동기구 접근을 확인한다. 최대 5명의 진행도 및 이름/레벨은 320/390/1024px UI fixture로 검수한다. 이것을 실제 5인 접속 시험으로 보고하지 않는다.
- 한글·영어 10자 닉네임 제한, SQL/HTML 형태 문자열 거부, 인증된 게스트 배지, 서버 저장을 검사한다. 휴대폰·토스 실기기 측정은 별도다.

## 온라인 보스 보간·정지 후 위치 보정 (2026-09-24)

- 보스 표시 위치를 응답마다 급격히 따라붙는 지수 감쇠에서, 이전 응답 간격에 따른 선형 보간으로 변경한다. 기상 자세도 응답 사이의 시간을 반영한다. 서버 전투 판정·보스 속도는 유지한다.
- 이동 시작/정지 입력은 전송 주기를 기다리지 않고 요청한다. 진행 중 요청이 끝나면 바뀐 입력을 즉시 전송한다.
- 손을 놓은 뒤 이전 이동 요청의 응답으로 화면 위치가 계속 밀리지 않도록 정지 승인까지 표시 위치를 유지한다. 정지 승인 후 남은 서버 위치 차이는 120ms에 보정하여 끝없이 미끄러지는 감쇠 꼬리를 없앤다. 피격·사망·강제 이동은 서버 상태를 우선한다.
- 코드 경로 확인 후 수정했으며 이번 수정의 자동 QA·성능 측정·실기기 재현은 실행하지 않았다. 지연 변동이 큰 연결의 보간 공백과 정지 시 최종 위치 보정은 실제 플레이 확인이 남아 있다.

## 20개 스테이지 펫 및 원형 마을 (2026-09-24)

- 기존 320 ID 가운데 일반 200종과 전용 드래곤 20종의 실제 모델을 24³로 제작한다. 단계별 대표 오브제, 몸 구조, 재질 색면과 얼굴을 데이터 및 모델에 반영한다.
- 1/12/20단계 파일럿 이후 20개 단계로 확장했고, 추가 컬러·오브제 개정은 12펫+3드래곤 비교 후 전체 적용한다. 비교 원본과 검수 결과는 `docs/art/stage-pet-review.md`에 연결한다.
- 시크릿 발견 규칙은 서버 관찰·개인별 중복 방지·저장 호환 검사를 포함한다. 기존 희귀도/성능/랜덤 전용 알 확률은 유지한다.
- 보스 리그 기상 연속성과 원형 기지 5농장·운동기구·길 방향·서버 공유 충돌·카메라를 함께 확인한다.
- 사용자가 요청한 구조·화면·획득·저장 검수만 실행한다. 실기기 성능과 실제 5인 공개 방 검증은 별도로 구분한다.

## 첫 여섯 펫 24³·도감 개선 (2026-09-24)

- 지정된 이름과 ID 0~5를 확인하고 콘셉트 → 독립 정수 복셀 원본 → 리그 → 개별 대기 동작 → 큰 도감 카드 순으로 구현했다.
- 실제 모델의 다각도·실루엣·동작 프레임과 6열/2열 비교 화면을 생성했다. 게임 도감의 WebGL 뷰어는 각도 변경·동작 정지·닫기 시 정리까지 확인했다.
- 범위·대칭 기관·리그 분할·연결성, 타입 검사, 320/390px 게임 UI 검수 통과. 실기기·전체 게임 회귀는 미실행이다.
- 편집 원본과 확장 기준, 수정한 시각 문제는 `docs/art/first-six-design-standard.md`에 기록한다. 기존 모델 수집 ID·보유 저장·보상 동작은 유지한다.

## 실제 서버 이동 진단 (2026-09-24)

- 사용자 허용 후 실제 Supabase 게스트 방과 현재 클라이언트로 프레임·위치·왕복 지연·CPU 표본을 측정했다. 상세 결과와 남은 한계는 `docs/qa/live-movement-report.md`에 기록한다.
- 확인된 첫 이동 오디오 초기화와 숫자 포맷터 반복 생성 비용을 수정한다. 이동 중 화면 보정 속도를 제한하고 지연 예측을 평활화한다.
- 서버 처리 구간별 시간과 CORS preflight 캐시를 추가한다. 서울 리전임을 확인했고 리전 강제 지정은 개선 근거가 없어 적용하지 않는다.
- 타입 검사 통과. 실제 HTTP 왕복 약 250ms는 남아 있으며 해결 완료나 실기기 FPS 향상으로 보고하지 않는다.

## 논블로킹 입력·통신 분리 (2026-09-24)

- fetch는 이미 비동기였다. 800ms 이동 중지 조건을 제거하고 프레임 기반 통신 호출을 독립 타이머/입력 상태/행동 큐로 분리한다. Promise는 개별 행동 응답을 기다릴 뿐 렌더 루프를 막지 않는다.
- 시뮬레이션 위치는 응답 시 교정하고 표시 오프셋으로 플레이어·펫·카메라를 부드럽게 연결한다. 매 프레임 서버 오차를 물리 이동에 더하던 처리를 제거한다.
- 왕복 지연을 보정한 서버 시각을 점진적으로 반영하고 게임 시계 역행을 막는다. 응답 콜백의 중복 HUD 갱신을 없애고 기존 프레임 갱신에서 처리한다.
- 행동 결과를 ID별로 저장/응답한다. 혼합 성공/실패 배치와 재전송 수동 회귀 사례를 추가한다. 준비 UI는 즉시 표시하며 서버 승인 전 진행 시간은 소비하지 않는다.
- 장기 단절 시 로컬 이동은 이어지지만 알/보상/타격은 서버 확정 전 완료되지 않는다. 복구 시 권위 상태로 보정한다. 자동 QA·검증 빌드·실기기 지연 측정은 실행하지 않는다.

## 이동 중 배트 PvP·이동 끊김 후속 (2026-09-24)

- Supabase attack 명령을 추가한다. 서버 위치·전방·거리·쿨다운으로 판정하고 공유 알 배열에 원래 알을 반환한다. 넉백은 기존 충돌 이동으로 진행하며 중복 타격/요청을 제한한다.
- 배트 pointerdown은 이동 포인터와 별도로 처리하고 클릭 중복을 막는다. 상대의 스윙 시각·피격·속도를 공유한다.
- 대각선 좌표 회전 후 1을 넘던 서버 입력을 정규화한다. 서버의 500ms 입력 소실 및 1초 활동 제한을 1.5초의 제한된 여유로 통일한다. 짧은 연결 지연에 즉시 이동을 끊지 않고 800ms까지 예측한다.
- 상대 위치는 프레임 시간 기반 보간과 제한된 속도 예측으로 갱신한다. 로컬 피격 이동도 서버 보상/피해 계산 없이 프레임 단위로 진행한다.
- 수동 rooms 회귀 사례에 전방 타격·알 유일성·이동 입력 유지·재전송·쿨다운을 추가한다. 자동 QA·검증 빌드는 실행하지 않는다. 실제 두 기기 지연/동시 터치 검증은 미실행이다.

## 서버 연결·게스트·기지 경계 후속 (2026-09-24)

- 서버 상태에서 routeCache는 제외하면서 routeStart만 복원하던 불일치를 수정한다. 두 캐시 항목 모두 저장/복원에서 제외하고 빈 경로를 재생성한다.
- 방 경쟁/요청 제한/만료 응답은 같은 요청 ID로 제한적으로 재시도한다. 인증 만료 시 한 번 갱신하고, 미분류 오류는 HTTP 상태와 진단용 콘솔 원인을 남긴다.
- Supabase 익명 로그인을 활성화하고 게스트 버튼과 세션 복구 제한 안내를 추가한다. 이메일 로그인과 기존 서버 저장은 유지한다.
- 기지 외곽 돌담과 입구 바닥·화단·등불·보급 상자를 정적 병합 및 공유 충돌 데이터에 추가한다.
- 원인 진단 중 실제 서버에 익명 인증·입장·정지/이동 갱신 요청은 200 응답이었다. 이 짧은 요청으로 사용자가 겪은 반복 오류 전체를 재현했다고 보지 않는다. 자동 QA·검증 빌드·스크린샷은 실행하지 않는다.

## 온라인 끊김·알 획득·맵 리워크 (2026-09-24)

- JSON으로 null이 된 최초 피격 시각 때문에 희귀 알 준비가 매 요청 취소되던 비교를 수정한다. 대기 중인 이전 요청과 자신의 행동 요청을 구분해 응답까지 기다린다.
- 서버 상태 복원 시 월드 재생성을 생략하고 충돌 구역·농장 인덱스를 재사용한다. 단일 game_read RPC와 검증된 인증 결과의 짧은 캐시로 순차 네트워크 조회를 줄인다.
- 플레이어의 작은 위치 차이와 보스의 이동을 보간한다. 획득·사망·피격·큰 위치 이동은 기존 서버 상태를 적용한다.
- src/world-art.ts에 마을과 스테이지별 대형 구조물을 작성한다. 지붕 형태가 다른 5개 농장, 광장·시장·연못·과수원과 20개 테마 구조물을 기존 정적 병합/인스턴싱에 통합한다.
- ROUTE.bossBaseScale=1.5로 모든 보스 기본 크기를 확대한다.
- 서버 산출물 생성·DB 마이그레이션·함수 배포 후 커밋·푸시한다. 자동 게임 검증은 요청에 따라 실행하지 않는다. 추후 수동 확인: 피격 전 희귀 알 준비 완료, 준비 중 이동/피격 취소, 동시 획득 경쟁, 높은 지연에서 이동 보정, 5개 농장 운동기구 접근, 스테이지별 구조물 가림과 모바일 프레임.

## Supabase 방·개인 농장·시크릿 드래곤 (2026-09-24)

- 이메일 후속 수정: 거부된 OTP 템플릿을 기본 config에서 분리하고 Site URL·redirect를 실제 게임 주소로 적용한다. 기본 링크 세션 감지, 기존 탭 로그인 상태 갱신, 메일 재요청, 선택적 코드 입력을 연결한다. 자동 QA나 테스트 메일 발송은 실행하지 않는다.

- 이메일 OTP와 방 찾기, 최대 5명 자동 배정, 방별 공유 알·보스, 개인 서버 저장. `server/room-engine.ts`에서 기존 게임 규칙을 재사용하고 `supabase/functions/game`에서 인증 및 원자적 저장을 처리한다.
- 클라이언트는 행동만 요청한다. 방과 개인 저장을 함께 커밋하며 경쟁·재전송은 revision과 요청 ID로 처리한다. 직접 저장 업로드·타인 자원 변경 API는 두지 않는다.
- 5개 농장·운동기구는 `src/village.ts`에 정의한다. 기지 공통 기본 속도와 소유자 슬롯을 사용한다.
- 기존 Secret을 보존하며 스테이지마다 전용 드래곤 1종과 전용 알을 추가한다. ID 300~319, 300종 저장을 320종으로 확장한다. 콘셉트·원본·실제 아이콘도 함께 저장한다.
- 외부 적용: `docs/supabase-setup.md`. 관리자 로그인·DB 마이그레이션·함수 배포·OTP 템플릿·SMTP가 필요하다. 공개 키만으로 완료했다고 보고하지 않는다.

- 시각: 모바일 캡처를 직접 검토한 후 의도한 UI/카메라/지형 경고 변경에 대해서만 기준 이미지를 갱신한다. qa:fast → 관련 E2E → 전체 verify → 프로덕션 프리뷰 E2E. 실기기 토스 검증은 별도로 남긴다.

## 추가 개정: 지역별 알·밤·펫 행렬 (2026-09-23)

- 20개 지역마다 독립된 20³ 알 조형 5개씩, 총 100개 외형을 사용한다. 색뿐 아니라 실루엣·장식 구조가 다르며 운반·보관·부화에도 외형을 유지한다. 기존 35알/100펫 보상 ID는 유지한다.
- 사용자 스테이지 선택 UI를 없앤다. 농장부터 1→20으로 이동하며 기존 바로가기 저장 위치는 연결 맵의 같은 지역 위치로 옮긴다. 개발 QA의 지역 fixture만 유지한다.
- 180초 주기 중 밤을 45초로 늘리고 실제 환경광·태양광을 부드럽게 낮춘다. 달·별과 낮밤 남은 시간으로 표시한다. 밤에도 탐험/알 회수가 가능하며 같은 밤 재접속으로 둥지를 다시 섞지 않는다.
- 펫은 플레이어 이동 경로를 한 줄로 따라간다. 좌우 분산을 없애고 크기에 맞는 간격, 경로 보간, 부드러운 방향 회전을 적용한다.
- `appearance-e2e`로 100외형 배치, 펫 직진/회전, 낮밤 표시, 선택 UI 제거를 검증한다. 모바일 캡처는 직접 확인하고 사용자 요청대로 기준 이미지 비교는 생략한다.


## 최신 사용자 개정: 연결된 20지역·스피드 성장·잠든 보스 (2026-09-23)

이 절은 아래의 독립 차원 반복 맵, 원정 제한시간, 밤 강제 귀환, 일반 피격 알 유지, 초반 보스 무피해 규칙보다 우선한다.

- 농장에서 앞으로 걸으면 1→20지역이 연결되고, 귀환할 때는 역순으로 통과한다. 사용자 차원 선택은 제거하며 기존 선택 저장은 연결 맵 위치로 변환한다. 일반 지역 길이는 32, 마지막 지역은 150으로 세 구역을 유지한다.
- 20번 지역 끝은 황금 장식의 닫힌 돌벽으로 막는다. 플레이어 이동·넉백 모두 벽 앞에서 멈추며, 지역 바로가기 출발에서도 같은 제한을 적용한다.
- 지역 진입 시 번호·이름·권장 스피드를 3초간 표시한다. 배너는 입력을 막지 않고 공격 예고와 겹치지 않는다. 역방향 진입에도 표시한다.
- 초기 기본 스피드 4.5→3.2. 원정 시간 만료로 실패하지 않으며, 밤은 색 변화·미수집 둥지 갱신만 담당한다. 운반/낙하 알을 빼앗거나 강제 귀환시키지 않고 입구도 막지 않는다.
- 스피드 강화·운동·트레일·펫으로 더 먼 지역을 편하게 탐험한다. 권장 스피드는 이동 거리(둥지까지 약 20초 목표)와 보스 추격 속도/대표 운반 속도 65%에 여유 0.5를 더한 값 중 큰 값이며 최소 3.2다. 시간 제한이나 입장 잠금 수치가 아니다. 원정 시간 강화·시간 특성의 신규 선택 UI는 숨기되 기존 소유값을 삭제하지 않는다.
- 지역마다 수호자 1명과 둥지 알 5개. 수호자는 눈을 감고 Z 표시로 잠들어 있다가 자기 알을 훔치면 분노 표시와 함께 추격한다. 알을 내려놓거나 맞아 놓치면 둥지로 돌아가 다시 잠든다. 재습득하면 다시 깨어난다. 12 거리 밖에서는 원격 공격하지 않는다.
- 보스는 잠든 동안 공격하지 않는다. 환경 장애물은 별도로 유지한다. 초반 보스도 공격 예고 뒤 10~12 피해를 주며, 초반 물살·증기 같은 환경 효과는 무피해를 유지한다.
- 직접 피격은 피해·1초 무적·0.28초 동안 2.4 넉백·알 낙하로 처리한다. 떨어진 알은 해당 위치에 1개만 남고 다시 주울 수 있다. 지속 독 피해는 넉백/낙하를 반복하지 않는다. HP0은 기존 자동 귀환과 70% XP 정산을 유지한다.
- 알의 카탈로그 region, 출처 stageId, 수호자 인덱스를 분리한다. 귀환 보상과 완료 기록은 알의 출처 지역에 적용한다. 기존 35알·100펫·구매·도감 ID를 보존한다. 구 저장의 임시 필드 둥지는 연결 맵으로 재생성하고 운반 알은 보존한다.

검증: `qa:fast`, 이동 기반 `connected-e2e`, 보스 수면/추격/낙하/재습득 `progression-e2e`, 기존 E2E, 42패턴 캡처, 20지역 렌더·GPU 검사, 빌드·성능·프로덕션 E2E. 사용자의 ‘이미지 비교 패스’ 요청으로 이번 실행만 `QA_SKIP_IMAGE_COMPARE=1`을 사용한다. 기본 비교 검사는 변경하지 않는다.

## GitHub Pages 배포 추가

- `main` push / 수동 실행 Actions에서 Pages를 배포한다.
