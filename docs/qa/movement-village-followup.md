# 이동 실측·마을·플레이어 표시 후속

2026-09-24. 실제 Supabase 익명 인증·방 API와 이 PC의 headless Edge(390×844)에서 측정했다. 위치를 직접 바꾸거나 서버를 모킹하지 않고 이동 입력으로 중앙 둥지까지 접근해 알을 집고 보스를 깨웠다. 휴대폰/토스 실기기 FPS 측정은 아니다.

## 이동

- 수정 전 정지 후 최대 표시 위치 변화: 전진 정지 0.314, 복귀 정지 0.301.
- 정지 시각 보정 후 첫 재측정: 0.014 / 0.011. 이후 정상 추격 실행: 0.025 / 0.045. 해당 정지 구간의 1초 이후 추가 이동은 0이었다.
- 응답 도착 시마다 따라붙던 보스 보간에서는 추격 표시 속도 10백분위가 0이었다. 서버 시각별 위치를 버퍼링한 뒤, 실제 응답에 0~250ms 지연 변동을 추가한 추격에서 10/50/90백분위가 1.350 / 1.500 / 1.650으로 측정됐다. 서버 이동 속도나 피해 판정은 변경하지 않았다.
- 버퍼링 실행의 추가 지연 환경 RTT 중앙값/95백분위: 363 / 570ms. 추격 프레임 시간 95백분위 18.1ms. 서버 오류 및 브라우저 예외 0.
- 최종 정상 네트워크 재측정: RTT 265 / 350ms, 정지 위치 변화 0.029 / 0.007, 추격 표시 속도 10~90백분위 1.350~1.650. 실제 게스트 로그인에서 잘못된 닉네임 거부와 `[GUEST] MoveProbe · LV.n` 표시도 확인했다.
- **지연이 큰 경우 정지 시 짧은 서버 위치 보정은 남는다.** 추가 지연 실행에서 정지 위치 변화 0.089 / 0.457이 관찰됐다. 무조건 끊김이 없다고 판정하지 않는다. 보스와 멈춘 플레이어의 접촉 후 발생한 넉백·알 낙하는 정지 오차와 따로 구분했다.

정지 보상은 서버가 보관한 최근 500ms 경로로 제한한다. 피격/알 상태/기지 경계가 바뀌면 이전 위치를 복원하지 않으며, 서버 충돌 이동을 통한다. 클라이언트 좌표·속도·재화는 받지 않는다. 보스 버퍼는 표시만 지연하며 긴 단절에서는 100ms 이상 추측 이동을 이어가지 않는다.

원시 자료: `artifacts/performance/live-movement-stop-baseline.json`, `stop-clock-fixed`, `final-chase`, `final-chase-jitter`, `buffered-chase-jitter` 및 각 CPU 프로파일. 같은 파일 이름 접두사 `live-movement-`를 사용한다. 방 난수·연결 상태는 실행마다 다르다.

## 추가 구현

- 플레이어 특성: 선택권·버튼·선택 화면·스탯 효과·서버 선택 명령 제거. 기존 레벨/경험치/펫/재화는 유지하고 구 특성 필드만 로드 시 폐기한다.
- 닉네임: 한글/영어 1~10글자. 숫자/공백/특수문자/보이지 않는 채움 문자 거부. 서버에서도 같은 검증을 사용하며 JSON 값으로 저장하고, 화면에는 `textContent`로 표시한다. 입력 제한만으로 SQL 처리를 안전하다고 가정하지 않는다.
- 게스트 표시: 검증된 Supabase 계정의 `is_anonymous`를 서버에서 전달한다. 클라이언트가 보낸 게스트 플래그를 신뢰하지 않는다. 머리 위 이름과 레벨 표시.
- 우상단: 내 위치와 같은 방 최대 4명의 현재 스테이지·거리·전체 진행 막대. 최종 스테이지의 긴 길이도 전체 진행 거리에 반영한다.
- 마을: 바깥 산맥, 열린 목재 문, 연결 울타리. 북쪽 출입 통로와 다섯 농장 운동기구 접근 유지.
