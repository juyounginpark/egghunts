# 로컬 멀티플레이와 로그인

Node 24 이상. 터미널 두 개에서 `npm run server:multiplayer`, `npm run dev -- --port 4317` 실행. 브라우저 두 창에서 게임을 열고 설정 → **게스트 로그인 · 친구와 걷기** → 모험 계속하기. 서버가 동일하면 다른 탐험가의 위치와 선택한 모자가 보인다. 가까이에서 상대를 바라보고 공격하면 배트를 휘두른다. 알 근처에서는 들고가기가 우선한다.

HTTP 서버는 기본 `127.0.0.1:4330`. 배포 주소가 제공되지 않았으므로 인터넷 서비스로 배포하지 않았다. 클라이언트 빌드의 `VITE_MULTIPLAYER_URL`이 없으면 프로덕션에서 임의의 로컬 서버로 연결하지 않는다. 다른 기기와 시험할 때는 서버 HOST와 정확한 MULTIPLAYER_ORIGIN, 클라이언트 VITE_MULTIPLAYER_URL을 일치시켜야 한다. WebView 출시는 HTTPS 서버가 필요하다.

토스 내부는 기존 `getUserKeyForGame` 식별자별 네이티브 저장소를 사용한다. 이는 외부 서버의 검증된 로그인 세션을 발급하는 OAuth 서버 구현과 다르다. 게스트 토큰은 서버가 암호학적 난수로 발급하고 클라이언트 메모리에만 둔다. 서버 재시작 시 게스트 세션과 공유 바닥 알은 초기화되며, 기존 로컬 인벤토리를 초기화하지 않는다.

서버가 처리하는 항목: 토큰 확인, 위치 범위/입력 형태, 상태 전송 빈도, 공격 전방·거리·쿨다운, 밀침과 넘어짐, 피격 알 공유 낙하, 한 명만 가능한 알 줍기. 상태는 약 10Hz 전송한다. 접속/오류 안내는 설정과 일시 토스트에 한정한다.

현재 각 클라이언트의 원래 알 스폰·부화·재화는 독립 실행이다. 상대의 운반 알과 PvP 낙하 알은 공유하지만, 모든 보스와 모든 원래 둥지가 서버에서 실행되는 구조는 아니다. 클라이언트가 보고하는 원래 운반 알과 속도를 서버가 전체 경제 모델로 재검증하지 않으므로 변조 방지 경제로 출시할 수 없다. 공개 서비스 전에는 서버 권위 월드/인벤토리, 토스 인증 검증, 데이터베이스, 재접속 보상·중복 거래 방지, 다중 방, 속도 검증과 운영 지표가 필요하다.

`node scripts/qa/multiplayer.mjs`: 실제 HTTP 요청으로 게스트 2명, 인증 실패, 잘못된 좌표, 배트 방향/쿨다운, 넘어짐, 낙하 알 선점 확인.

`node scripts/qa/multiplayer-e2e.mjs`: 서로 다른 브라우저 컨텍스트 두 개의 로그인 → 공격 → 상대 넘어짐 → 알 낙하 → 공격자의 줍기를 확인. 외부 서버나 실제 토스 앱 테스트가 아니다.
