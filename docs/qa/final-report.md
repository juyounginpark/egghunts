# 최종 구현·검증 보고


## 2026-09-23 최종 추가 검증

- 20지역 × 5알 = 100가지 고유 20³ 조형. 실루엣 좌표 중복 없음, 격자 경계 검사 및 외형 메타데이터 운반/귀환/저장 테스트 통과.
- 스테이지 선택 UI 제거. 기존 선택 저장은 동일 지역의 연결 맵 위치로 변환한다.
- 펫 일렬 추종, 간격/회전 경로 보간 적용. 모바일 직진·회전 E2E 통과.
- 밤 45초/180초, 조명 전환·달/별·남은 시간 표시. 같은 밤 재접속 둥지 중복 재생성 수정. 밤 중 로컬 멀티플레이 강제 귀환/알 회수 차단 제거.
- `QA_SKIP_IMAGE_COMPARE=1 npm run verify` 통과: lint/typecheck/unit, 기존·성장·멀티·연결20지역·외형 E2E, 42공격 패턴, 20지역 GPU, 성능, 프로덕션 E2E. 기준 이미지는 갱신하지 않았고 모바일 캡처를 직접 확인했다.
- 측정: 개발 초기 전송 3,652,804 bytes, 프로덕션 JS gzip 196,161 bytes. 최대 측정 draw calls 94, triangles 58,066. 반복 장면 전환 GPU geometry 75→75. 이는 데스크톱 Headless Edge/SwiftShader 측정이며 실기기 FPS가 아니다.
- 토스 인증·안전영역·리더보드 실기기 검증은 별도다. 로컬 게스트 멀티플레이와 가상 광고를 정식 인증·수익화로 간주하지 않는다.


## 최신 개정: 체력·레벨·환경 회피

2026-09-23. 아래 기존 보고의 필드 회복·피격 알 낙하·PvP 버튼·사망 광고 선택은 이번 요청으로 대체되었다.

1. **기획서 변경**: 문서 앞부분에 최신 규칙과 충돌 해결 기준 추가. 1~4 안전, 5부터 피해, HP0 자동 귀환, 원정 XP 70% 유지. 마지막 요청에 따라 HP는 머리 위 바이며 최대치에서 숨긴다.
2. **구현**: 레벨/XP/HP 및 최초 보상 이력 저장, 연속 레벨업, 6특성 선택과 효과, 방어 패시브 확장 지점. 피격 무적 1초·넉백·둔화, 비치명 피해에서는 알 유지. 기존 저장 ID/구매 능력치 유지. 공격 버튼 제거, 로컬 멀티플레이 이동 유지.
3. **스테이지**: 20차원 선택과 권장 레벨·피격 횟수 안내. 41개 데이터 정의, 1~4 무피해 학습과 5 촉수 2종, 이후 직선/추적/부채꼴/파동, 엄폐, 물살, 석화, 자석, 시계, 웅덩이. 20차원은 거리별 3구역과 기억 패턴 최대 두 종류.
4. **검증**: `qa:fast` 통과(17 게임 + 22 시스템 + 19 성장/위험 + 11 서버 검사 및 밸런스 시뮬레이션). 성장 E2E 3흐름 통과. 최초 HP UI E2E는 렌더 프레임 전 가시성 확인으로 실패하여 실제 표시를 기다리도록 수정 후 통과. `build`, `build:toss` 성공. 나머지 전체 회귀 결과는 이번 세션 완료 기록을 아래 추가한다.
5. **디자인**: 360px 피격·저체력, 차원 선택 직접 검토. 상단 HP 패널을 없애고 머리 위 78px 바 적용, 최대 HP 및 귀환/부화 시 숨김. 예고선은 큰 알에 가려지지 않고 토스트는 조작 버튼 위에 표시. 픽셀 2배 확대 유지.
6. **성능**: 지형/예고/공격은 공유 InstancedMesh 풀 3개. JS gzip 합계 약 182 kB(빌드 출력). 정확한 실행 측정은 artifacts/performance/performance.json 참조. 데스크톱 SwiftShader 측정은 모바일 실기기 FPS 보장이 아니다.
7. **앱인토스**: 어댑터 오류 처리·저장·점수 문자열 회귀 통과. 실제 로그인, 네이티브 저장 재실행, Safe Area, 백그라운드, 햅틱/소리와 저사양 FPS는 실기기 검증 필요. AIT 파일 생성은 앱 출시/배포 완료를 의미하지 않는다.
8. **남은 문제·우선순위**: (1) health-balance-report.md의 실제 피격 횟수와 목표 조율. 고정 피해 및 비례 피해 상한을 임의 변경하지 않았다. (2) 41개 패턴은 공통 복셀 연출 기반이며 압축기 벽 이동·랩터 기절 자세·발구르기 3회 진동 등 세부 전용 애니메이션 보강 필요. (3) 실제 앱인토스 저사양 장시간 테스트. 방어 패시브 타입은 연결했으나 기존 펫에 새 능력을 임의 배정하지 않았다. 기존 35알/100펫은 그대로이고 140종 새 아트는 생성하지 않았다.

따라서 핵심 성장·피격·귀환 흐름은 동작하지만, 모든 스테이지 세부 연출과 목표 피격 횟수까지 최종 완료된 것으로 표시하지 않는다.

## 이전 구현 기록 (최신 규칙과 충돌하는 내용은 위 개정 우선)

2026-09-23. 로컬 Windows/Edge 환경. 실제 토스 앱 출시 승인과 외부 서버 배포는 수행하지 않았다.

## 구현 결과

복셀 농장과 5지역, 알 획득·운반·귀환·유실·부화, 펫 착용/도감 보상, 운동/트레일, 체력·보스 예고, 밤 장벽, 로컬 게스트 PvP, 판매 스토어, 가상 광고·사망·부활을 연결했다. 최신 요청은 트레일 적용 후 실제 운동 증가량 표시, 매초 숫자 이펙트, 10^7 단위 A~Z/AA/AB 포맷이다. HUD에는 m/s나 별도 트레일 배수 나열이 없다.

## 기획 검증 결과

공통 밤과 개인 탐험 시간을 분리했다. 밤은 180초 주기 첫 10초, 농장 내부 이동 가능. 펫 시간 능력은 제거하고 클릭/오토/스피드 배율로 바꿨다. 판매 후에도 발견 이력을 보존한다. 기존 5지역·100종 저장을 삭제하지 않았으며 4세계 출시·20세계 확장은 별도 제작/이관 계획이다. 상세 문제·수정·검증 계약은 planning-review와 implementation-plan 참조.

결정적 10분 모델에서 첫 알 16.1초, 첫 부화 18.8초, 강화 12회. 일반 등급·적극적인 수동 입력을 가정한 시뮬레이션이며 모든 사용자의 체감이나 희귀 당첨을 보장하지 않는다. 상세 표는 artifacts/qa-summary/balance-report.md.

## 디자인 검증 결과

6개 뷰포트 × 26개 상태의 156장 캡처. 360×800, 390×844, 412×915, 1080×1920, iOS Safe Area 형태, 320×568을 포함한다. 펫 라벨 배경/높이, 두꺼운 알 선택선, 밤 팝업 과밀, 헤더 줄바꿈, 운동 피드백을 수정했다. 대표 화면 직접 검토와 전체 DOM/이미지 비교를 구분한다. 상세 기록은 design-review.md.

## 테스트 결과

`npm run verify` 최종 통과: ESLint/TypeScript 오류 0, 기존 게임 17개 + 단위 22개 + 서버 통합 11개, 플레이 E2E 12개, 두 브라우저 PvP, 156장 이미지 비교, 성능 예산, 프로덕션 빌드와 스모크 모두 통과했다. 기존 check-ui도 수정 후 전체 통과했다. 실패 기준을 낮추거나 테스트를 삭제하지 않았다.

`npm run build:toss`도 통과해 `alkong-expedition.ait`를 생성했다. 이 명령은 로컬 빌드이며 콘솔 업로드/서비스 배포는 하지 않았다. 최종 소스 변경 이후 qa:lint를 다시 통과했다.

| 명령 | 검증 범위 |
|---|---|
| npm run qa:fast | ESLint·TypeScript·17 기존 게임 검사·22 단위 검사·밸런스·11 HTTP 멀티플레이 검사 |
| npm run qa:e2e | 핵심 A~D를 포함한 12개 플레이 시나리오와 두 브라우저 PvP |
| node scripts/qa/visual.mjs --capture | 실제 렌더링 캡처와 DOM/픽셀 배율 확인 |
| node scripts/qa/visual.mjs --update | 직접 검토한 디자인 변경 기준 156장 저장 |
| npm run qa:visual | 같은 시드/시간의 156장 허용 오차 비교 |
| npm run qa:performance | 요청·draw call·geometry·프레임·gzip 예산 |
| npm run verify | 위 전체 QA + 프로덕션 빌드 + 빌드 산출물 스모크 |
| npm run build:toss | 타입 검사·웹 번들·AIT 산출물 |
| node scripts/check-ui.mjs | 기존 6뷰포트·가로 화면·2배/3배 픽셀·100종 UI 회귀 |

기존 check-ui의 첫 실행은 페이지 이동 직후 초기화 전에 `data-mode`를 읽어 실패했다. 로딩 요소가 아직 없는 상태도 hidden으로 판단되던 테스트 준비 문제였다. QA hook과 모드 준비를 기다리도록 수정한 뒤 동일 단언 전체가 통과했다. 준비 대기 외 기준은 바꾸지 않았다.

프로덕션 스모크는 QA hook 제거, 부화실/도감/상점 동작을 확인한다. A~D 전체 플레이는 개발 QA 모드에서 실행하며 프로덕션에서 같은 전체 플레이를 자동 재현했다고 주장하지 않는다. CI 파일은 추가했지만 원격 CI 실행은 아직 하지 않았다.

## 성능 결과

최종 측정은 artifacts/qa-summary/performance-report.md와 artifacts/performance/performance.json에 저장한다. 복셀별 Mesh 없이 greedy meshing, 공유 지오메트리, 입자 InstancedMesh, 미소유 펫 지연 로딩을 사용한다. 예산은 초기 전송 4MiB/JS gzip 300KiB/draw calls 250/triangles 500,000이다.

실측: 준비 870ms, 개발 초기 전송 3,360,593 bytes(70개 모델 JSON), 프로덕션 JS 629,313 bytes/gzip 171,338 bytes(약 167.3KiB). 기본 62 draw calls/24,232 triangles, 거대 펫 장면 96 calls/27,422 triangles. 프레임 간격 중앙값 6.1ms·p95 12.2ms·최대 24.2ms. 12회 전환 후 geometry 78개/texture 1개로 유지했다.

측정은 데스크톱 Edge SwiftShader, 네트워크 제한 없음, 180프레임·12회 화면 전환이다. 모바일 60FPS 달성, 장시간 메모리 안정성, 8인+다수 거대 펫의 최악 상황을 검증한 결과는 아니다.

## 앱인토스 상태

어댑터 자동 검사: 네이티브 저장 순서, 점수 문자열 변환, 선택 API 실패 처리, 정리/폴백. 브라우저 저장·재실행과 로컬 게스트 멀티플레이는 자동 검증한다. 실제 토스 앱 사용자 식별, 순위 반영, 네이티브 Safe Area·가시성·저장, 지원 버전/콘솔 승인은 **실기기 검증 필요**다. 가상 광고는 실제 광고 수익화가 아니다.

## 남은 문제

- 공개 HTTPS 서버·토스 인증 검증 서버·DB·서버 권위 월드/경제가 없다. 현재 로컬 게스트 서버만 제공한다.
- 20세계 고유 장애물과 140종, 출시 28종으로의 저장 이관은 제작 기획 단계다. 기존 100종을 보존했다.
- 실제 모바일 장시간 성능/터치 사용성/네이티브 API와 전체 프로덕션 플레이 재검증이 남았다.
- 브라우저 클라이언트 저장은 악의적인 수치 변조를 방어하는 경제 서버가 아니다.
