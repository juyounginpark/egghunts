## 구현 범위

- 일반 펫 200종과 드래곤 20종의 실제 정수 복셀·리그·VOX·320px 아이콘을 교체했다. 본체 범위는 24³이다. 기존 0~99 펫과 플레이어는 유지했다.
- 20개 스테이지 보스와 최종 보스의 형태·색·리그를 다듬었다. 기존 기본 크기 1.5배, 전투 속도·피해량은 유지한다. 잠든 위치에서 몸 높이와 눈을 단계적으로 열며 일어난다.
- 같은 몸 위 같은 장식을 돌려 쓰던 방식을 펫별 대표 오브제로 바꾸었다. 새순·부표·사물함·방독면·망원경 등 오브제의 실루엣, 연결 위치와 재질을 다르게 만든다. 초원/산호/사막의 닮은 대표 몸은 별도로 낮은 부유체·넓은 사막 발·옆으로 펴진 귀로 구분했다.
- 모델 안에 재질별 색면을 기록한다. 식물은 성장 방향, 용암은 뜨거운 중심, 금속은 접합부와 앞면, 빙하는 색층, 직물은 접힌 가장자리, 공허는 절단면으로 구분한다. 전역 그라데이션 필터나 무작위 점을 쓰지 않는다.
- 눈꺼풀·눈동자 방향·눈썹·입과 얼굴 면에 차이를 주었다. 팔다리와 눈의 대칭을 검사하고, 손에 든 물건·구부러진 몸·은하 드래곤의 다른 높이 날개는 의도적인 비대칭으로 기록했다.
- 일반 기관은 몸에 연결된다. 외계의 감각판과 공허 조각만 의도적으로 분리된다. 리그별 병합 메시를 사용하며 복셀마다 Mesh를 만들지 않는다.
- 대기는 고개·귀·꼬리·날개·쥔 오브제의 움직임과 타이밍을 달리한다. 부화 시 2.4초 인사 후 대기로 이어지며, 스테이지 문양과 등급별 음수/문양 수가 다르다. 확인 버튼은 처음부터 활성화되어 즉시 넘길 수 있다. 동작 감소 설정도 따른다.
- 도감은 긴 설명·보상·확률을 접고 이미지와 이름을 먼저 배치한다. 미발견 전용 드래곤은 실루엣과 단서만 표시하며 전체 모델 뷰어를 열지 않는다.
- 기지는 원형 땅·순환길·중앙 분수·진입로와 다섯 개인 농장으로 재배치했다. 농장 문은 순환길을, 시장 건물 문은 진입로를 바라본다. 운동기구와 농장 슬롯 번호는 같은 개인에게 귀속된다. 이동 충돌을 서버와 공유한다.

## ID·성능·저장 및 획득 호환성

| 범위 | 처리 |
|---|---|
| 0~99 | 기존 펫 유지 |
| 100~299 | 기존 스테이지 일반 펫 200개 ID에 외형 교체 |
| 300~319 | 기존 전용 드래곤 20개 ID에 외형 교체 |
| 이름·stageId·slot·tier | 변경 전 Git 카탈로그와 비교해 동일 |
| 일반 희귀도 배분 | 단계별 C 2, B 2, A 2, S 1, SS 1, SSS 1, SECRET 1 |
| 전용 드래곤 | 단계별 SECRET 1종 추가로 구분 |
| 등급 확률·능력 배수·판매/수익 수치 | 유지 |
| 기존 랜덤 전용 알 | 기존 SECRET 내 50% 분기 유지 |
| 발견 단서 보상 | 스테이지 기믹 달성 시 개인별 1회 전용 알 추가 지급 |
| 기존 100/300/320 저장 | 수량·장착·판매 후 발견·수령 보상 유지, 누락된 단서 필드는 빈 값으로 초기화 |
| 구버전 variant 5 알 | 원래 스테이지의 전용 드래곤으로 부화 |

시크릿 조건은 단순 확률의 대체 모델이 아니라 플레이로 확정 발견할 수 있는 추가 경로다. 기존 알 확률을 디자인 때문에 변경하지 않는다. 각 스테이지의 회피·운반 회피·흡인 영역 탈출·깊은 구간 도달·양쪽 위험 구간 탐험 등의 조합을 서버가 관찰한다. 클라이언트가 재화·완료 여부·좌표를 제출해 보상을 얻는 방식은 사용하지 않는다. 저장 및 요청 재전송 시 같은 알을 중복 지급하지 않는다.

## 검수와 한계

- [구조 검사](character-structure-audit.json): 기존 포함 341개 캐릭터의 범위, 리그 분할, 눈/대칭 기관, 연결성 확인. 외계와 공허의 의도적인 부유 부품은 분리 기록을 남긴다.
- [저장·획득·개인 농장/서버 검사](stage-integration-audit.json): 320 ID, 구버전 저장, 20개 발견 규칙, 7개 희귀도 부화, 조작된 요청 거부, 중복 지급 방지, 기지 입구와 5개 운동기구 접근 확인.
- [렌더 검사](stage-render-all-audit.json): 220종의 다각도·실루엣·회색·대기/인사 프레임.
- [모바일/UI 검사](stage-ui-audit.json): 320/390px 도감, 확대 뷰어, 부화 연출, 보스 기상, 원형 마을 확인.
- 서버 방 회귀와 Pages 빌드도 수행했다. 공개 서버 실사용자 5인 동시 플레이, 실제 모바일/토스 기기 성능, 20개 발견 조건을 사람의 수동 플레이로 모두 완주하는 검사는 별도다.
- 변경한 `src`와 새 검수 스크립트의 lint는 통과했다. 전체 저장소 lint에는 기존 `first-six`, `first-six-ui`, `live-movement`, `rooms` QA 파일의 전역 이름/미사용 변수 오류가 남아 있어 전체 lint 통과로 보고하지 않는다.
- 실루엣이 중복되지 않는다는 구조 검사와 “모두 갖고 싶다”는 미적 판단은 다르다. 모든 펫이 같은 정도로 매력적이라는 객관적 통과를 주장하지 않으며 비교 화면에서 개별 판단할 수 있게 했다.

## 재현

아래 명령은 수동 검수용이며 자동 실행 정책을 바꾸지 않는다.

```text
python scripts/rework_stage_pets.py --bosses
python scripts/qa/character-geometry.py
node scripts/qa/stage-pet-review.mjs
node scripts/qa/stage-integration.mjs
node scripts/qa/stage-final-review.mjs
```

기존 `rework_characters.py` 호환 진입점은 마지막에 새 스테이지 원본을 적용하므로 오래된 50³ 템플릿으로 덮어쓰지 않는다.
