# 신규 380종 적용 기록 — 2026-09-27

사용자가 전달한 [제작 지시](add-380-characters-prompt.md)를 바탕으로 기존 카탈로그 뒤에 신규 수집 펫을 추가했다. 기준 커밋은 `256987d`다.

## 실제 개수와 배분

| 구분 | 기존 | 신규 | 최종 |
| --- | ---: | ---: | ---: |
| 스테이지 1개 | 11 | 19 | 30 |
| 스테이지 20개 | 220 | 380 | 600 |
| 이전 도감 | 100 | 0 | 100 |
| 주간 보상 | 1 | 0 | 1 |
| 전체 런타임 카탈로그 | 321 | 380 | 701 |

| 등급 | 단계별 기존 | 단계별 신규 | 단계별 최종 | 20단계 최종 |
| --- | ---: | ---: | ---: | ---: |
| C | 2 | 5 | 7 | 140 |

| SECRET | 2 | 0 | 2 | 40 |

기존 SECRET은 일반 20종과 드래곤 20종이다. 문서의 예시 목표보다 SECRET이 단계당 1종 많으므로 기존을 보존하고 부족분에 19/20을 곱한 뒤 최대 나머지 방식으로 신규를 배정했다. 최종 C는 예시보다 1종 적다. 목표표와 완전히 일치한다고 주장하지 않는다.

신규 영구 ID는 321~700이다. `01-N01`~`20-N19`와의 일대일 대응은 [ID 매핑](expansion-id-map.json)에 있다. 누락된 신규 ID·중복 ID·신규 이름 충돌은 없다. 기존 0~320의 이름·능력치·등급·연결을 변경하지 않았다.

## 구현

- 380개 각각 모델 JSON, 파트별 리그/설계 JSON, 실제 렌더링 PNG를 추가했다. 기존 생성기는 수정하지 않고 `expansion_models.py`, `expansion_details.py`, `expansion_recipes.py`에 신규 해부 구조와 소품을 둔다. 재생성 시 동일 ID 파일을 갱신한다.
- 몸통·주둥이·눈 위치·사지·꼬리·날개 및 대표 소품을 조합한다. 신규 380개는 색 정보를 제외한 복셀 좌표가 모두 다르다. 이는 기하 중복 검사이며 디자인의 질을 자동 판정하는 검사는 아니다.
- 신규 전용 대기 동작은 파트 피벗과 모티브에 따라 흔들림·회전·호흡·날개·소품 동작을 적용한다. 효과 축소 설정에서는 정지한다. 문장별 세부 연기(물방울 낙하, 한입 베어 먹기 등) 전체를 독립 시퀀스로 구현한 것은 아니며, 공통 동작 계열로 단순화한 항목이 있다.
- 유리 계열 파트는 새 모델이 명시적으로 요청할 때만 복제한 투명 재질을 사용한다. 기존 공유 재질과 기본 그림자 설정을 보존한다. 정적 농장 모델도 리그의 형태와 크기를 유지하도록 병합한다.
- 새 종은 기존 스테이지/등급 공용 알의 결과 풀에 들어간다. 알 모델·등급 총확률·SECRET 전용 경로·무게 생성 규칙은 유지한다. 기존 종류의 등급 내 개별 절대 확률은 풀 확대만큼 감소한다.
- 신규 터치/자동/스피드 배율은 기존 동일 단계·등급 평균이다. 평균은 기존 최솟값~최댓값 안이며, 균등 추첨의 등급별 기대 보너스를 유지한다. 실제 장기 플레이 경제 시뮬레이션 결과를 뜻하지 않는다.
- 도감은 30종을 표시하며 마지막 ID 700까지 접근할 수 있다. 321칸 기존 저장은 뒤에 0을 붙여 확장한다. 기존 소유·장착·발견·보상 수령·알 정보는 유지한다.

## 실행한 검증

이번 전달 문서가 검증을 명시적으로 요청하여 아래 항목을 실행했다.

- `node scripts/qa/expansion.mjs`: 기존 321개 레코드 전체 동일성, 기존 자산/정의 파일 2,908개 SHA-256, 기존 manifest 항목, 380개 신규 ID/이름/기하 중복, 전 단계 등급 수, 등급별 기대 보너스, 기존/신규 저장 왕복, 신규 380개 부화 결과 및 기존 SECRET 40개 경로 확인.
- `node scripts/render-expansion.mjs`: 실제 Three.js 렌더러로 380종 전체 썸네일 생성, 정적/리그 경계 일치, 대기 동작 전후 이미지 차이 확인. 스테이지별 기존 1종+신규 19종 비교 시트 20장을 눈으로 검토했다. [전체 갤러리](expansion-gallery.html)에서 개별 이름·등급·썸네일을 확인할 수 있다.
- `node scripts/qa/expansion-ui.mjs`: 데스크톱 Edge의 390×844 화면에서 기존/신규 동행 모델 혼합, 스테이지 20 도감 30칸, 마지막 ID 700 이미지/부화 결과, 가로 넘침 및 JS 오류 확인. 초기 진입에서 신규 모델 전체 선로딩이 없었다.
- `npm run build:pages`: TypeScript 검사와 Pages용 Vite 빌드 성공.
- `node scripts/qa/expansion-budget.mjs`: 이전 커밋의 동일 빌드를 비교하여 전체 JS 청크 gzip 증가량 측정.

검증 출력과 비교 이미지는 로컬 `artifacts/expansion/`에 있다. 코드/모델/썸네일과 재실행 스크립트는 커밋하며 임시 빌드·브라우저 출력은 커밋하지 않는다.

## 성능 및 미확인 범위

- 전체 JS 청크 gzip: **322,389B → 330,434B (+8,045B)**. 300KiB=307,200B 예산을 넘는다. 기존 빌드도 초과했고 이번 변경이 추가 증가를 만든다. 예산 통과로 보고하지 않는다.
- 신규 단일 모델 렌더링은 876~5,802 triangles다. 혼합 동행 UI 검사 장면은 93 draw calls, 80,542 triangles였다. 전체 월드 최악 조건이나 실기기 성능을 보장하는 수치가 아니다.
- 기본 파트 경계의 최저점은 -0.0295~0.00000002였다. 일부 기울어진 파트의 반 복셀 이내 접지가 남아 있으며 모든 애니메이션 프레임의 관통을 자동 판정하지 않았다.
- 실기기 FPS, 초기 전송 4MiB, 모든 무게/운반 자세 조합, 모든 단계의 장시간 멀티플레이, 실제 토스 인증/안전영역/리더보드는 이번 검사에서 측정하지 않았다.
- 모델 380종과 획득 연결은 모두 포함했다. 세부 연기의 문장별 완전 일치 및 위 성능/실기기 항목까지 완료했다는 의미는 아니다.
